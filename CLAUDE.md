## What this is

"Magic Swipe": an Android app (Expo SDK 58, React Native, TypeScript, Expo Router) to build Magic: The Gathering decks as if holding a handful of cards — swipe right adds the card to the active deck, swipe left discards it, arrows browse. Product framing: "cards in your hands", never "Tinder". Cards come from the Scryfall API; decks are stored locally in SQLite (no backend, no login). UI text is in Spanish.

It's a port of the web app in `../frontmagic` (React) + `../apimagic` (Express/MySQL). Those used api.magicthegathering.io and a server-side DB; this app deliberately uses Scryfall and local storage instead.

## Commands

```bash
npx expo start --go            # dev server for Expo Go (expo-dev-client is installed, so plain `expo start` targets a dev build)
npx expo start                 # dev server for the development build (APK with native modules: OCR)
npx tsc --noEmit               # typecheck  (also: npm run typecheck)
npx expo lint                  # ESLint with React Compiler rules (also: npm run lint)
npx expo-doctor                # dependency/config diagnostics
npx expo export --platform android --output-dir <tmp>   # verify the Android bundle compiles
```

There are no tests yet.

**npm 12 quirk:** `npx expo install <pkg>` updates `package.json` but its internal `npm install` fails with `EALLOWSCRIPTS`. Run plain `npm install` afterwards. Keep `react-dom` pinned to the same version as `react` (expo-router's web deps otherwise pull a newer `react-dom` and npm fails with ERESOLVE).

## Architecture

- **Layout.** `src/app/_layout.tsx` nests `GestureHandlerRootView` → `SQLiteProvider` (migrations via `onInit`) → `AppStateProvider` → headerless `Stack` + `LoadingScreen` (logo + version from `expo-constants`, shown over everything until `ready` and at least 1.4 s, fades out). Tools are **tabs at the top** in `src/app/(tabs)/` (`tabBarPosition: 'top'` + custom `components/AppTabBar`: app header "Magic Swipe" + ⚙ settings sheet, then a segmented control using each screen's `title` + `tabBarIcon`; screens therefore don't pad the top inset, and `DeckBar` / the collection pad the bottom one): `index.tsx` = "Construir" (the card swipe, where the app opens — keep it first and central: the app's idea is having cards in your hands), `collection.tsx` = "Colección", `life.tsx` = "Vidas" (life counter: `components/life/LifeCounterScreen`, pure state in `src/life/game.ts` saved as JSON in `settings` key `lifeCounter`; 2-6 players, top row rotated 180°, left/right half −1/+1, long press ±10, poison + commander damage per opponent (also takes life), who goes first, dice; `expo-keep-awake` while focused). Add future tools as another file + `<Tabs.Screen>` in `(tabs)/_layout.tsx`. On Construir: `TopBar` (one-row filter bar) → `SwipeArea` → `deck/DeckBar`; filters, deck and history open in `BottomSheet` (RN `Modal`).
- **Collection** (`components/collection/`, DB v4 `collection_cards`): one row per printing (`scryfall_id`: edition + language). Search box filters owned cards and searches Scryfall (debounced `searchCards`; Scryfall's autocomplete doesn't know Spanish names) to add in `prefs.language`. `OwnButton` (📦 above the swiped card) adds the printing on screen. The deck sheet shows owned/missing copies via `getOwnedCounts` (summed over printings by `oracle_id`). When cards are missing, "🛒 Cardmarket" in the deck sheet header opens `deck/MissingCardsModal`: tap a card → Cardmarket search by English name; "📋 Copiar lista" (expo-clipboard) copies `N Name` lines to paste into a Cardmarket wants list ("Añadir lista de mazo"). **Filters + grouping** (`src/collection/organize.ts`, pure: `applyFilter`, `groupCards`; panel `collection/CollectionFilterPanel` in a `BottomSheet`, applied live): color (from the mana-cost symbols), main type, mana value (computed from the cost string; lands = 0), rarity, set, language, € per copy, used in a deck (`getDeckOracleIds`) and 2+ copies. Group chips (Color, Tipo, Edición, Rareza, Coste, Precio) make collapsible sections with copies + value; the list is flattened into header/card/gallery-row items. **📷 Scanner** (`collection/CardScanner`, `src/scan/recognizeCard.ts`): expo-camera photo → on-device OCR with `expo-text-extractor` (Google ML Kit; native, so **not in Expo Go** — `scanSupported` is false there and the scanner explains it) → `parseCardText` reads set code + language ("DMU • ES") and collector number from the bottom lines and name candidates from the top → `/cards/:set/:number/:lang`, accepted only if the name agrees, else fuzzy name (checked, it guesses wildly) or name search preferring an exact name, moved to the read set/language.
- **Why sheets:** an earlier version animated collapsible panels by hand with RNGH; the custom drag gestures competed with buttons, list scrolling and the card swipe and felt unreliable. Keep custom gestures to the card swipe and the bar-only `DeckBar`. Sheets are dragged closed from their grip and from any `SheetDragArea` (exported by `BottomSheet`, own pan per area, vertical only so horizontal lists still scroll); the deck sheet wraps its whole fixed top part (summary whose cover + arrow drops down the `DeckPicker` like a select (closes on pick), collection line with view switch + buttons toggle, one-line validation banner whose details open in a popup, actions) in one, and its cards scroll below in a separate list. Never wrap a vertical list in a `SheetDragArea`. `expandable` sheets (the deck) have three stops — hidden, open (`heightRatio`), full screen — laid out at full height and translated down, with bottom padding while at the open stop so content isn't cut off. A drag-close finishes its own ease-out animation (`dragClosing`); the `visible=false` effect only animates closes from buttons/backdrop.
- `src/components/deck/DeckSheet.tsx` — port of the web's MazoConstructor + Mazos: deck actions (edit/save name+format, list/gallery, share list, clear, delete), `DeckPicker` (deck tiles; tap = load, ＋ = new), then the cards in three views: list (full details + qty/remove/cover/share), gallery (3 columns, `small` thumbnails) or big (one full-width card per row). Removing a card (🗑, with confirmation, or − below 1), clearing or deleting the deck shows an undo bar for 6 s (`snapshotDeck` / `restoreSnapshot` re-insert the raw rows, same deck id). No swipe-to-delete anywhere: deck and collection rows share `components/CardControls` (`QuantityStepper`, `CardIconButton`, `UndoBar`). Collection rows: stepper, ⓘ info, add to the active deck, share, 🗑 (confirm + undo via `snapshotCollectionCard` / `restoreCollectionRow`).
- `src/components/filters/FilterPanel.tsx` — edits a **draft** of the filters and applies it with "Buscar" (top of the sheet). Keyword and set lists come from Scryfall catalogs, memoized in `scryfall.ts` (`cached`).
- `src/context/AppState.tsx` — shared state: deck list, active deck + its cards, filters; active deck id and filters persist in the SQLite `settings` table. Call `refresh(deckId?)` after every DB write. `ensureActiveDeck()` auto-creates "Mazo sin nombre" on the first right swipe (the web's "(Not Saved)"); "💾 Guardar" in the deck sheet names it. A new `filters` object identity is what triggers a new search. Bump `FILTERS_KEY` when the `Filters` shape changes.
- No user accounts (the web/API had JWT login); everything is local and auto-saved.
- `src/icons.ts` / `assets/mtg/` — mana, rarity, format and type icons copied from `../frontmagic/src/Media`. SVGs are black, so render them with expo-image `tintColor`. Assets are typed as `IconSource` (`number`), not RN's `ImageSourcePropType`, which doesn't fit expo-image's `source`.
- `src/components/HistorySheet.tsx` (▤ button by the card counter): thumbnails of swiped cards with their decision, the current one highlighted, and upcoming ones. Infinite scroll: reaching the end shows 40 more and calls `queue.loadUpTo(n)`, which keeps fetching Scryfall pages until `n` cards are loaded.
- `src/hooks/useCardQueue.ts` — paged card stack for the current filters. Results are tagged with the `filters`/`attempt` they belong to so stale responses are ignored; position resets during render when the search changes (no setState in effects); fetches the next page when ≤8 cards remain and prefetches upcoming images.
- `src/components/SwipeCard.tsx` — the draggable card. Gesture Handler **v3 hook API** (`usePanGesture`, `onUpdate`/`onDeactivate`) with Reanimated 4; callbacks run on the UI thread and report back via `scheduleOnRN` (from `react-native-worklets`; `runOnJS` is deprecated). Buttons trigger the same animation through an imperative `swipe(dir)` handle. Render it with `key={card.id}`.
- `src/api/scryfall.ts` — `Filters` → Scryfall query string (`buildQuery`), and maps Scryfall cards to the flat `Card` type (double-faced cards take images from `card_faces`). All requests go through a throttle (≥100 ms apart) and send `User-Agent` + `Accept` headers, which Scryfall requires. A 404 `not_found` means "no results", not an error.
- `src/db/database.ts` — schema, migrations and all queries (no ORM).
- **Deck stats + sample hand** (`deck/DeckStatsScreen`, chart-bar button; pure maths in `src/deck/stats.ts`): totals, land-count advice (35-38 per 100, ~40 % for 60), stacked mana curve (creatures / others, 7+), color symbols vs land sources (`landColors`), types; sample hand from the library without commanders (shuffle, London mulligan picking the bottom cards, draw) and the hypergeometric odds of 2-4 lands. "Recomendar maná" (`LandRecommender`, Arena-like): `recommendLands` adds the missing basics (37 % of the exact commander-style size, added even if the deck goes over it — the validation banner reports it; ~40 % / min 24 constructed) split by color-source deficit vs mana symbols, restricted to the commander identity; undo restores a `snapshotDeck`. Charts are plain `View`s, no chart library.
- **Synergies** (`src/api/synergy.ts`, not Scryfall): EDHREC through the JSON its own site loads (`json.edhrec.com/pages/{cards,commanders}/<slug>.json`, unofficial, may change; `edhrecSlug`, ids are Scryfall ids) and Commander Spellbook's public API (`/variants/?q=card:"…"`, `POST /find-my-combos`). Shown in the card info screen (`cardInfo/CardSynergy`) and the deck's 🧩 screen (`deck/DeckSynergyScreen`: combos included / one card away, EDHREC recommendations for the first commander with ＋ to add, shown as list / gallery / swipe — `RecommendSwipe` reuses `SwipeCard`, so that Modal is wrapped in `GestureHandlerRootView`). Shared UI in `synergy/SynergyParts`.
- **Live card data** (`getCardDetails` in `scryfall.ts`, hook `useCardDetails`): prices in € (Cardmarket trend), direct Cardmarket product URL, P/T / loyalty / defense and tokens (`all_parts`) per printing, fetched via `/cards/collection` and cached in memory for the app run — never stored (prices change daily). Scryfall doesn't price most non-English printings, so those are priced with the English printing of the same set + collector number. Used for the deck price (`DeckSummary`), per-card price/stats in the list view, the Cardmarket popup total, the deck's tokens (`TokensModal`) and the collection value. Mana costs render as Scryfall symbol SVGs (`ManaCost`, `/symbology`). The ⓘ button on each deck card opens `cardInfo/CardInfoScreen` (full-screen Modal over the sheet): the raw `/cards/:id` object grouped in sections with a Spanish label + explanation per field (`cardInfo/fields.ts`), faces, legalities grid, related parts, rulings and links; image-size fields are deliberately omitted and unknown fields fall into "Otros datos".

## Conventions / gotchas

- **No limits when adding.** Any card/quantity can go into a deck; `src/validation.ts` (`validateDeck`, pure) checks the deck against its format and the deck sheet shows a ✓/⚠ banner plus per-card red marks. Rules: size (100 commander-style, 60 oathbreaker, ≥60 constructed), copies per `oracle_id` (1 singleton / 4, restricted = 1 in Vintage, basics and "any number" / "up to N cards named" exempt), legality from stored Scryfall `legalities`, commander (👑 `is_commander`; eligibility, max 2 with Partner/Friends forever/Background) and color identity.
- DB v3 stores `color_identity`, `legalities` (JSON) and `is_commander` per deck card; rows saved before v3 are backfilled from Scryfall (`/cards/collection`, 75 ids per request) when their deck is opened.
- **Schema changes:** bump `DATABASE_VERSION` in `src/db/database.ts` and add a new `if (version === N)` step; never edit the existing step. `PRAGMA foreign_keys = ON` is set on every start (deleting a deck cascades to its cards).
- **Undo** history lives in `SwipeArea`; each entry records which deck the card was added to so undo still works after switching decks. It is reset when filters change because it relies on positions in the result list. Each entry stores its `position`, so undo jumps back to it (`queue.goTo`) even after browsing. The ‹ › arrows on the card browse without deciding; tapping a history thumbnail jumps there (long press = preview). Decisions are kept per card id, so a revisited card shows "✓ Ya añadida" / "✕ Descartada".
- With the React Compiler lint rules: use `sharedValue.get()/.set()` instead of `.value`, and don't call `setState` synchronously inside `useEffect` (adjust state during render or set it from async callbacks).
- Icons: `@expo/vector-icons` (`MaterialCommunityIcons`, bundled in Expo Go) for the deck sheet's action row; most other buttons still use emoji/text symbols.
- Deck covers use Scryfall's `art_crop` image, derived from the stored `normal` URL (`artCropUrl`).
- **Settings** (`SettingsSheet`, ⚙ in `TopBar`): `prefs` in `AppState` (persisted under `prefs`; add new fields to `DEFAULT_PREFS`): default card language, haptics (`expo-haptics`), default deck view (list / gallery / big).
- **Languages:** searches return English printings (no language filter). With `prefs.language` ≠ 'en', `useCardQueue` swaps the current + next 4 cards to that language in the background (`getCardInLanguage`: same set first, then any set; cached; a language picked by hand isn't overridden). The 🌐 pill above the card (`LanguagePicker` → `getCardLanguages`: `oracleid:X lang:any`, `unique=prints`, `include_multilingual`) swaps the current card for another language's printing via `queue.replaceCurrent`; adding it stores that printing's name/image. The 🎨 pill (`ArtPicker` → `getCardArts`: `unique=art`, in the card's language first, then English artworks it lacks) swaps the artwork the same way. Name search uses unquoted `name:word` terms (quoted ones don't fold accents) and, if no English name contains the words, retries with `lang:any` so Spanish names work. `o:` and `t:` only match English oracle text/types.
